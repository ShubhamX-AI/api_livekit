1. Summary

The SDK went from 1.8.2 to 1.8.8 in a month. Most of the new headline features are LiveKit Inference (Cloud-only), which this platform cannot use. The self-hostable parts that are worth having here:

  1. GPT-6 models (gpt-6-luna, gpt-6-sol) for the cascade LLM. LiveKit already marks gpt-5.1 and gpt-5.4-nano deprecated, retiring 2027-04-01, with GPT-6 as the named replacements.
  2. GPT-Live, OpenAI's full-duplex voice model, through openai.realtime.GPTLiveModel. It runs on our OpenAI key. It does not fit any of the three existing modes, so it would be a fourth mode.
  3. New TTS models: ElevenLabs eleven_v4 / eleven_v4_turbo (a small allowlist change) and Sarvam bulbul:v4-flash (larger: Sarvam TTS is pinned today, and v4-flash has its own speaker roster of about 220 names).
  4. Answering machine detection (livekit.agents.AMD) for outbound calls. It works self-hosted when we pass our own LLM and STT.
  5. Small wins from the bump itself: prompt-cache breakpoints sent by the Responses LLM for GPT-5.6 and later, e2e_latency for realtime replies, sticky LLM fallback routing.

There is also one risk to check that is not about new features. LiveKit Inference retired the GPT Realtime 1.5 and 2 ids and now lists only gpt-realtime-2.1 / -2.1-mini. Our default is DEFAULT_REALTIME_MODEL = "gpt-realtime-1.5" (src/core/model_support/capabilities.py:31). That retirement is on LiveKit's gateway, and api.openai.com may still serve 1.5. We have no working key, so this is unknown.

4.2 Realtime and duplex

ModelSelf-hostNotes
gpt-live-1 (GPT-Live)plugin openai.realtime.GPTLiveModel(voice=, delegation="responses", responses_options={model, instructions, reasoning, text, service_tier, tool_choice, max_output_tokens}). Needs a paid OpenAI tier. Constraints that hit this codebase:
  • No text modality, so it cannot pair with our TTS. It is not pipeline.
  • session.say() raises without a TTS. The prerecorded greeting (assistant_greeting_audio, played via session.say(audio=...)) breaks, and so do any filler or hold features that use say.
  • Instructions and voice are fixed for the session. Mid-session instruction updates raise RealtimeError. There are two instruction sets: the voice persona, and responses_options.instructions for the backend.
  • Barge-in needs an explicit VAD. The session drops its default VAD for this model. inference.VAD(model="silero") is local, so this is fine.
  • Usage arrives as RealtimeModelMetrics.session_duration (voice, billed by seconds) plus LLMMetrics under the backend model's name. src/core/agents/usage.py needs a new fold and a price row.
  • Voice aster was replaced by cedar in 1.8.8.
gpt-realtime-2.1, gpt-realtime-2.1-miniverifyListed only under LiveKit Inference. Not in the core RealtimeModels Literal on main (gpt-realtime, -1.5, -2, -2025-08-28, gpt-4o-realtime-preview). 5. Upgrade notes for 1.8.2 → 1.8.8

  • Dependency floors: openai>=3.19,<4, mcp>=2.2,<3, websockets>=17.1,<17.2, OpenTelemetry >=1.45,<1.46, onnxruntime>=1.30,<1.31 (turn detection). Check docker/requirements-agent.txt and docker/requirements-control.txt. The control image pins openai for the live checks in openai_live.py.
  • Breaking changes that touch us: the removed OpenTelemetry Events API, if we emit events; tools continuing asynchronously after an interruption timeout. Not relevant: Anthropic httpx2, inference.RealtimeModel isinstance.
  • Sarvam STT now closes the streams it collects (1.8.6). This is worth having for sarvam_parallel.py.
