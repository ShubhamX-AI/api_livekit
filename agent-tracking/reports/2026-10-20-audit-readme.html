Findings

Overdone: duplication with docs/

R-01 High Duplicated documentation: feature deep-dives

README.md:37-243, 535-592

About 330 lines describe single features in depth: provider keys, the four validation gates, the Exotel lifecycle, queue states, the Meeting Calls topology, passthrough, hold detection, assistant modes, the audio library, and max call duration. Each topic already has a page under docs/; the mapping is in research.

Why it matters: two copies drift apart. That has already happened: docs/getting-started/index.md:29 still says "three execution modes" while the README says four, and the README's own queue description is stale (R-03). Every feature change now has to edit the README as well as the docs. AGENTS.md's Definition of done even lists the README as one of the places to update.

Fix: use Move Function at the documentation level. Delete each section from the README and keep a single "Documentation" list that links to the docs page for each topic. Before deleting a section, check whether it holds a fact the docs page lacks, and move that fact into the page first.

R-02 High Missing: no working local quickstart

README.md:265-273, 349-373; docker-compose.yml

The Requirements section lists MongoDB ("a replica set in production") and a LiveKit server. Run Locally then starts at uv sync. Nothing explains how to get MongoDB or LiveKit running locally, and docker-compose.yml defines only api, sip_dispatcher and agent. The cp .env.example .env step appears in the env section, not in the run steps. There is also no "make your first call" step.

Why it matters: for a "how do I run this" README, this is its main job, and today a new developer gets stuck at step 1. The dispatcher also uses Change Streams (dispatcher.py:755), which fail on a standalone mongod. So even in development, MongoDB must run as a single-node replica set, and the README does not say so.

Fix: write a numbered quickstart: (1) start MongoDB as a single-node replica set and run livekit-server --dev (or add both to a dev compose profile); (2) cp .env.example .env; (3) uv sync; (4) start the server and the worker; (5) one curl to create a key, then a link to docs/getting-started/ for the first assistant and call.

R-04 Medium Project Structure is a file-level tree (132 lines)

README.md:594-724

The tree lists individual files down to silero_vad.onnx and digest_auth.py. A tree this detailed goes stale every time a file is added. It is correct today, but it is also a near copy of AGENTS.md → ## Project structure.

Fix: show the top-level layout (src/api, src/core, src/core/agents, src/core/model_support, src/services, tests, scripts, docs, docker) with one comment each, in about 20 lines. Then link to AGENTS.md for the layering rules.

R-05 Medium The same mode description appears three times

README.md:12-16, 537-563; speaks_first at 17 and 563

The four modes are explained in the feature list and again in Assistant Modes. The speaks_first note appears twice word for word, and both are repeated a third time in docs/architecture/runtime-modes.md.

Fix: use one four-row table (mode, what runs, vendor, needs TTS?) and link to runtime-modes.md and compatibility.md for the rules.

R-06 Medium Run Locally mixes four jobs

README.md:375-438

Local dev, Docker image selection, two-host production deployment, capacity tuning advice, and two data backfill scripts all sit under "Run Locally".

Fix: keep local dev and tests in the README. Put the deploy steps (deploy.sh, image roles) under a short "Deploy" heading or in docs/architecture/dependencies.md. The backfill and normalize scripts are one-off migrations, so they belong in docs/changelog.md or the troubleshooting page, which already mention them.

R-07 Medium Endpoint table is 50 rows

README.md:478-534

The table is accurate (all 50 routes match src/api/routes/), but it duplicates docs/api/ row by row. The README standard asks for a quick-reference table, not a full one.

Fix: use one row per router (14 rows): prefix, auth, purpose, and a link to its docs/api/<resource>/ page. Keep /health as its own row because it always returns HTTP 200.

R-08 Medium Design rationale and agent rules in the README

README.md:49-53, 76-80, 94-96

The README carries the story of the silent-call failure, the line "Every set is measured, never copied from a doc page", and the rule "Never edit a model list from memory". The first two are design rationale; the third is a contributor rule that AGENTS.md already states.

Fix: delete them from the README. The Diagnostics table can stay as a short "Useful scripts" list, or move to docs/reference/troubleshooting.md, which already has it.

Stale or wrong

R-03 Medium Dispatcher polling is described wrongly

README.md:117-120 vs src/services/outbound_dispatcher/dispatcher.py:804-828

The README says the dispatcher "polls the queue every 2 seconds (fallback poll every 30s when idle)". In fact the loop is event-driven. Change Streams wake it, and a 30 s timeout acts only as a safety net. The asyncio.sleep(2.0) at :484 waits for a bridge process to exit; it does not poll the queue.

Why it matters: an operator tuning queue latency would look for a 2 s knob that does not exist.

Fix: R-01 removes this section anyway. If it stays, write: "wakes on a MongoDB Change Stream; 30 s safety-net poll".

R-09 Low Status note about unfinished work

README.md:191-194

"The remaining work is in the connector repository: convert the prototype into a LiveKit AgentServer…" This is a roadmap item, and it goes stale the day the work is done. docs/guides/meeting-connector.md already describes the contract.

Fix: delete it, or move it to the open-questions file of the meeting-calls plan.

R-10 Low "All three" scripts, but four are listed

README.md:91

The Diagnostics table lists four scripts, but the line below it says "All three are read-only unless --apply is passed".

Fix: say "All four", or drop the sentence along with R-08.

R-11 Low mkdocs commands lack uv run

README.md:455, 461

mkdocs is a project dependency (pyproject.toml:15-16), not a global tool, so a bare mkdocs build --strict fails unless the virtualenv is active. AGENTS.md:80 already uses uv run mkdocs build --strict.

Fix: use uv run mkdocs build --strict and uv run mkdocs serve.

R-12 Low Capacity advice contradicts the defaults

README.md:415-419

The README suggests "Set MAX_CONCURRENT_JOBS=20 in production", but the code default is 12 and AGENTS.md says the caps must be set from a load test. An unmeasured number in the README tends to get copied.

Fix: delete the number. Keep "one sip_dispatcher across all servers" and "pin the Exotel IPs to the control-plane host", since both are real constraints.

R-13 Low "Dispatcher starts with the API process" is only half true

README.md:101

That is true only while ENABLE_DISPATCHER=true. In production the dedicated sip_dispatcher owns it, as the README's own Architecture section says.

Fix: removed by R-01; otherwise add "(or in sip_dispatcher in production)".

R-14 Info Open-source bar: licence and contributing

repository root

There is no LICENSE and no CONTRIBUTING.md. The README says so honestly. For the internal audience that was agreed, this is fine. If the code is ever published, add both, and move the "how to work in this repo" content (tests, lint, docs build) from AGENTS.md into CONTRIBUTING.md.

  • Endpoints: all 50 routes are listed with the correct prefix and auth.
