Facts the old docs had wrong (now match the code)

  • The worker stops taking jobs at 1.0 × MAX_CONCURRENT_SESSIONS, not 0.9 × MAX_CONCURRENT_JOBS. Inbound INVITE setups default to 24, not 8.
  • There is a third capacity bucket, meeting (default 4). The orphan reaper runs every 30 minutes. A dispatch is tried at most 3 times.
  • The web token comes from POST /web_call/get_token, not GET /api/get_token. Meeting calls use near_field noise reduction. The input guard is also skipped in duplex.
  • The two gpt-4o-*realtime-preview models are not on the allowlist. The control and agent Dockerfiles live in docker/. The Exotel bridge is started by the dispatcher.
  • Inbound failure codes 486, 487, 503 and 400 were added. The unauthenticated POST /call/end_call echo is now documented.

Behaviour surface: unchanged

  • HTTP API: no route, schema or response changed. The src/ edits are comments only.
  • Public site URLs: every page that existed still answers. The 9 architecture URLs redirect to concepts/ (built pages checked in site/architecture/). Deep anchors inside them land at the top of the new page.
  • MCP: it still indexes docs/ only (src/api/mcp_docs.py unchanged), so dev-docs/ is never served. Search ranks concepts/duplex.md first for "duplex gpt-live how it works".
  • Tests that read docs: tests/test_provider_pricing.py passes, because docs/reference/pricing.md kept every rate row.
