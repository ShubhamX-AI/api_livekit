3. Method

core-be-workflow → core-be-debug: each finding re-read at its file:line, fixed at the narrowest layer, with a regression test that was run against the old code (by stashing the fix) to prove it fails there. The bridge fix was additionally proven with a real forkserver child started from a __main__ that never configures logging. Two subagents reviewed the diff: a fresh-context correctness reviewer and a simplicity reviewer; their findings and what was done are in section 6.

4. Current → Target

Why a log-only redactor. redact_text masks every 32+ character token. That would also mask queue_id (32 hex), every UUID id and the SIP Call-ID — the ids calls are traced by. redact_log_text keeps the same rules but lets a token through when it contains such an id and nothing credential-sized is left beside it. Longer hex secrets (40-hex Deepgram key, sk_+hex, 64-hex signatures) are still masked, and URL credentials (scheme://user:pass@) are masked too. HTTP error bodies keep using redact_text, unchanged.
