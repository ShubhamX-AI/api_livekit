1. Summary

You asked to add the newest self-hostable models: OpenAI (e.g. GPT-6), and new STT and TTS models. This change does that and adds OpenAI GPT-Live as a fourth assistant mode, duplex. Every model id was confirmed against the live OpenAI account before it was added. Each new parameter combination was probed against the real API, and every acceptance rule is covered by a test. Existing assistants behave exactly as before: no default changed.

7. Open: step 8, manual calls (needs you)

Deploy the agent image first, then the API. A 1.8.2 worker would treat a duplex row as pipeline.
  1. Create a duplex assistant with one tool and speaks_first: true (example in docs/api/assistant/create.md, Duplex tab).
  2. Web call: check that you hear a greeting, that a barge-in stops the playback, that the tool round-trips, that the webhook arrives, and that UsageRecord.llm_session_duration > 0 with pricing_complete: true.
  3. Exotel outbound: check that the agent stays silent during ringing and greets after answer.
  4. Run one cascade call on gpt-6-luna and one pipeline call on gpt-realtime-2.1.

8. Out-of-scope observations

  • ElevenLabs rates updated to the current list (follow-up): $0.08 per 1K characters for v4, v3 and multilingual v2; $0.04 for v4 turbo, v3 conversational, turbo and flash.
  • Text-to-dialogue (v3/v4) drops similarity_boost, style and use_speaker_boost, but the schema says voice settings "apply to all models". Since our own HTTP client is used rather than the plugin, worth re-checking with a live call.
  • mcp_docs.search_docs ranks by raw term count, so new docs keep pushing short, relevant pages down. A length-normalised score would fix it.
  • gpt-5.1 and gpt-5.4-nano removed from the allowlist (follow-up). Run uv run python scripts/migrate_retired_models.py --apply after deploy to move stored assistants to gpt-6-sol / gpt-6-luna.
  • gpt-6-astra and gpt-6.1-sol are served but not allowlisted. Not added.
