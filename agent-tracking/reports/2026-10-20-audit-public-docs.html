Public docs audit (MkDocs + MCP)

Slug 2026-10-20-audit-public-docs · 2026-10-20 · target docs/ as served by MkDocs and by /mcp · report only

Summary

The structure is complete; the accuracy is not. Every route has a page, every page is in the nav, and the MCP serves all 96 pages. The reference pages (models, pricing, defaults) match the code. But an integrator who follows the docs exactly hits a wall on the first day in several places. The trunk example in Getting Started returns 422. A web chat client listens on the wrong topic and never sees a reply. Error bodies are shown in a shape the API never sends. And a web client cannot learn which LiveKit server to connect to.

Fix first: the web chat topic and LiveKit URL (H1, H2), the Getting Started trunk body (H3), and the error envelope and status codes across all pages (H4).

What is already right

  • Nav covers every .md under docs/. All 50 routes have a page. The MCP indexes 96 pages, and list_docs, get_doc and search_docs work.
  • All 7 create and 6 update example bodies on the assistant pages pass the real Pydantic schemas.
  • pricing.md lists every rate key; models.md lists every model id except three OpenAI STT ids. Every factory default matches.
  • The end-call webhook's retry and timeout rules, end reasons and statuses; the tool webhook's request and reply handling; the inbound-context request and fallbacks; queue status; meeting call; and auth (401/403).

Method

  • Lead: nav vs files, routes vs pages, and live MCP search_docs on 10 questions. Spot-checked H1 (SDK constants), H3 (schema), H4, H5, H7 and H11, and the redirect SSRF, against code.
  • Three read-only investigators, each with code as the reference: (1) assistant, tools, audio, auth, errors, including running the doc examples through the schemas; (2) calls, telephony and all three webhooks; (3) analytics, admin, reference pages, and an 18-question MCP readiness walk.
  • One investigator claim was rejected after checking: AGENTS.md no longer references docs/architecture/.
